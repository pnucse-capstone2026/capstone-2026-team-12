# 금융 판례 직접 검수 스프린트 11 — 7행 채택

> 검수일: 2026-09-03  
> 원문: 법제처 국가법령정보센터 판례 전문  
> 반영: `data/real_clause_labels_sprint11.csv` (`train` 7행, 전부 A등급)

## 채택 기준

1. 공식 판결문에서 계약·약관·상품설명서 문구와 그 문구에 관한 판단을 함께 확인한다.
2. 구두 영업 멘트, 당사자 주장, 법원의 법리 요약은 실제 조항과 섞지 않는다.
3. 내용 무효, 설명의무 위반, 제한해석, 유효 적용을 note에서 구분한다.
4. 같은 사건의 독립 조항은 동일 split에 배치한다.
5. 신규 행은 전부 `train`에 두어 공식 Test와 기존 test split을 봉인한다.
6. 기관투자자 사건은 법리는 유효해도 일반 금융소비자 분포에서 별도 집계한다.

## 검수 중 제외한 후보

- `2015나20071`의 “3개월 6.3%”는 설명의무 위반을 뒷받침하지만 구두 영업 멘트라 계약 조항 골든셋에서 제외했다.
- `96가합17321`의 연 14.7% 수익보장 각서는 무효 판단이 명확하지만 기관 간 개별 보장약정이고 현재 10종 위험유형에 정확히 대응하지 않아 제외했다.
- `2007나53442`의 중도환매 수수료 5% 문구는 하급심만 보면 안전 후보였으나, 같은 사건의 대법원 `2008다52369`가 실제 환매가격 하락 위험을 수수료 때문에만 손실이 생기는 것처럼 오해시키는 부실 표시라고 판단했다. 스프린트 7에 이미 위험으로 있어 새 안전 행은 폐기했다.
- `2011다112407`과 `2024다215375`는 좋은 투자 사례지만 각각 스프린트 8과 스프린트 3에 이미 있어 중복 채택하지 않았다.
- 같은 `2024가합22393`의 계정정지 조항들은 기존 스프린트 3 행과 의미가 겹쳐, 독립적인 시스템 오류 거래취소 조항만 추가했다.

## 성능 재측정 원칙

- 데이터만 `train`에 추가한 지금은 공식 Test를 다시 돌리지 않는다. 모델·프롬프트·라벨 판정 로직이 변하지 않았으므로 기존 예측도 변하지 않는다.
- 먼저 스프린트 11만 별도 진단해 과잉경보(FP)가 어느 문구에서 나는지 기록한다. 이 값은 개발용 기준선이며 공식 성능으로 발표하지 않는다.
- 진단 결과를 바탕으로 모델·프롬프트를 실제로 바꾼 뒤에만 전체 회귀·정상계약서 FP·금융 진단을 돌린다.
- 최종 후보가 동결되면 봉인된 공식 Test 40을 한 번만 재측정한다. 반복해서 보고 고치면 test 오염이다.
- 금융 성능을 별도 주장하려면 이번 train 행을 재사용하지 말고, 사건 단위로 분리한 신규 A등급 금융 held-out 30~40행을 따로 확보한다.

## 현재 모델 1회 개발 진단 — 공식 성능 아님

2026-09-03 현재 프롬프트와 worker로 스프린트 11만 한 번 실행했다. 단발 실행이고
train 표본이므로 외부 발표용 성능 수치로 사용하지 않는다.

| 항목 | 결과 |
|---|---:|
| 입력 | 7 |
| 유효 판정 | 5 |
| 전체 폴백 | 2 (`2011다69053`, `2001다61852`) |
| 유효 판정 정확도 | 60.0% (3/5) |
| 전체 입력 기준 정확도 | 42.9% (3/7, 폴백은 오답 처리) |
| 유효 판정 혼동행렬 | TP 0 / FP 2 / FN 0 / TN 3 |

- `2005다29771` 상환시기 조항을 `주의/보증금 반환 지연`으로 잘못 읽었다. 투자신탁
  상환금을 임대차 보증금 유형으로 오인한 도메인 FP다.
- `2024가합22393` 시스템 오작동 거래취소 조항을 `위험/일방적 계약 해지`로 잘못
  읽었다. 객관적 발동요건과 장부 오류 정정이라는 제한을 충분히 반영하지 못했다.
- 유일한 위험 행이 폴백되어 이 단발 결과로 Recall을 평가할 수 없다. 보고용 진단은
  API 상태가 안정된 때 3회 반복 다수결로 다시 측정해야 한다.
